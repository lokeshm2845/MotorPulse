# MotorPulse — AI sound check for farm pumps and motors

**Hear a pump failure before it happens.** MotorPulse turns a budget smartphone into an AI stethoscope for machines.
A farmer records 10 seconds of a running pump; the phone compares it with *that pump's own* healthy sound fingerprint,
gives a 0–100 health score, a Green / Yellow / Red verdict, a likely cause and a spoken next step in English, Hindi or
Marathi — fully offline.

## What works in this prototype

| Feature | Status |
|---|---|
| Installable phone app (PWA), works fully offline after first load | ✅ |
| 10-second microphone recording with raw audio (no noise suppression / auto-gain) and live level meter | ✅ |
| Recording quality gate (too short, too quiet, clipping, unsteady sound) with spoken-language guidance | ✅ |
| Per-machine enrolment: 3 healthy recordings → sound fingerprint (stored on the phone) | ✅ |
| On-device AI: log-mel features → two calibrated anomaly detectors → 0–100 health score | ✅ |
| Explainable fault hints: bearing wear, cavitation / dry running, imbalance / looseness, electrical | ✅ (rule-based) |
| Trend engine (EWMA + CUSUM) and severity rules | ✅ |
| Advice, typical repair cost, voice output in English / Hindi / Marathi | ✅ |
| History chart, share report with a mechanic (WhatsApp / share sheet) | ✅ |
| Offline outbox → idempotent sync to the server (results only, never audio) | ✅ |
| Fleet dashboard for FPOs / panchayats / workshops | ✅ |
| Demo pump with simulated recordings of 4 fault types | ✅ |

## Run it

Requirements: Python 3.10+ and Node 18+ (Node only for tests and evaluation).

```bash
pip install -r server/requirements.txt
python -m uvicorn server.main:app --host 0.0.0.0 --port 8000
```

* Phone app: <http://localhost:8000/app/> → tap **Try the demo pump**, or **Add machine** to use your own pump.
* Fleet dashboard: <http://localhost:8000/dashboard>
* API docs: <http://localhost:8000/docs>

The microphone needs a secure origin. `localhost` works on a laptop; to open the app on a phone, serve it over HTTPS
(for example `ngrok http 8000`, or host the `app/` folder on GitHub Pages / any static host).

## Tests and evaluation

```bash
node --test tests/engine.test.mjs        # DSP, linear algebra, quality gate, trend, end-to-end on simulated faults
python -m pytest -q server/test_server.py  # API: idempotent sync, validation, fleet summary
node tests/run_samples.mjs               # result table on the simulated recordings
node ml/eval_dcase.mjs data/dcase2020_pump/pump 3 5   # real-data evaluation (DCASE 2020 pump, 3-clip enrolment)
```

Regenerate the simulated recordings: `python ml/make_demo_audio.py app/samples`.

## How it works

```
10 s audio ─► quality gate ─► log-mel features (64 bands, 1 s windows, 50% overlap) + descriptors (68-d)
          ─► detector A: PCA reconstruction error (linear autoencoder)
          ─► detector B: Mahalanobis distance, shrinkage covariance
              (both fitted on this machine's own healthy recordings, calibrated leave-one-recording-out)
          ─► fused z-score ─► health 0–100 ─► trend (EWMA + CUSUM) ─► severity ─► fault hints ─► advice + voice
```

All of this is plain JavaScript in `app/engine/` (no ML library, ~25 KB), so the same code runs on the phone and in
the Node tests and evaluation.

## Project layout

```
app/            phone app (PWA): UI, i18n, offline storage, recorder, sync, service worker
app/engine/     on-device AI engine: dsp.js, model.js, faults.js, trend.js
app/samples/    SIMULATED demo recordings (generated by ml/make_demo_audio.py)
server/         FastAPI sync API + fleet dashboard (SQLite in the prototype; PostgreSQL/TimescaleDB in production)
ml/             simulated-audio generator, DCASE evaluation script and results
tests/          engine tests and sample runner
```

## Honest limitations

* Fault *causes* come from physics-informed rules tuned on simulated faults; a trained classifier needs labelled field data.
* Hindi / Marathi text is the team's translation; voice uses the phone's built-in text-to-speech (Bhashini planned).
* Demo recordings are simulated and labelled `SIMULATED` everywhere they appear.
* Repair costs are rough typical ranges, not quotes.
